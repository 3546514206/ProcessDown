## 图表类型选择决策指引（用户未指定类型时按此选择）

判断顺序：先看内容特征是否命中下表某一类，命中即用对应图类型；都不命中才退回 `flowchart`。多特征命中时优先选更具体的非 flowchart 类型（如"用户路径"同时像步骤流程，选 `journey`；"订单状态流转"同时像流程，选 `stateDiagram-v2`）。

| Git 提交历史/分支演进 | `gitGraph` |

> C4 五层选择：`C4Context`=系统全景与外部角色；`C4Container`=容器/进程级分解；`C4Component`=容器内组件级分解；`C4Dynamic`=运行时交互场景；`C4Deployment`=部署拓扑节点。组件分解用 Component，运行时调用场景用 Dynamic。
> 依赖图边界：系统/服务间部署依赖用 `architecture-beta`；代码模块/函数调用依赖用 `flowchart`。

> 关键反偏置：看到"部署拓扑""系统架构""微服务部署"不要用 flowchart（用 C4 或 architecture-beta）；看到"分类层级""体系""界门纲目"不要用 flowchart（用 mindmap 或 classDiagram）；看到"演进""阶段""大事记"不要用 flowchart（用 timeline 或 stateDiagram-v2）。注意"组织架构/汇报关系"是 flowchart（人员层级），不是系统架构。
> "流程"二字反偏置：用户说"流程"但实为状态流转（待支付->已支付->已完成，强调状态与触发条件）用 `stateDiagram-v2`；实为多方交互（前端/后端/数据库请求响应顺序）用 `sequenceDiagram`；仅当是步骤/审批/判断/分支执行流时才用 `flowchart`。
> 其他高发反偏置：多方交互/请求响应顺序用 `sequenceDiagram`；数据库表字段外键用 `erDiagram`；类属性方法继承用 `classDiagram`；用户路径/体验路径用 `journey`；占比/百分比/份额用 `pie`；数值走势/波动用 `xychart`；集合重叠/差异用 `venn-beta`--均不要默认 flowchart。
> 易混淆判别：`timeline`（事件/里程碑按时间排列，无工期依赖）vs `gantt`（任务有工期与前后依赖）；`erDiagram`（数据库表+字段+外键）vs `classDiagram`（类+属性方法+继承关联）；`quadrantChart`（仅 2 个维度定位）vs `radar-beta`（3 个及以上维度对比）；`timeline`（事件时间线，无状态触发）vs `stateDiagram-v2`（状态机，有触发条件/循环/分叉）。

## 通用语法安全规则（必须遵守）

1. **禁止 Emoji**：不得使用任何 Emoji 字符，用文字替代（如 [通过]、[失败]）
2. **禁止中文标点**：所有标点用英文半角（`,;:.()[]{}`），不得用中文全角（`，；：（）【】`）
3. **节点文本为纯文本**：严禁 HTML 标签（`<b>`/`<i>`/`<div>` 等）--resvg 不渲染，PNG 导出会丢失。**例外**：换行符统一使用 `<br/>`（flowchart 显式开启 Markdown 字符串模式时也用 `<br/>`，不要在字符串里敲原生回车或 `\n`）
4. **缩进用 4 空格**，不要用 Tab
5. **行尾不要多余空格**
6. **不要在关键字（end/else/alt 等）所在行加注释**：`%%` 注释会吞掉同行后续所有语法
7. **节点文本含 `()`/`[]`/`{}` 等定界字符必须用双引号包裹**：`id1["This is the (text)"]`
8. **节点 ID 命名硬性约束**：节点/组件 ID 必须仅由英文字母、数字、下划线组成（`[a-zA-Z0-9_]`）。绝对禁止在 ID 中包含：
   - 中文（如 `用户登录`）
   - 空格或横线（如 `user-login`、`user login`）
   - 任何标点（`.`、`-`、`/`、`@` 等）
   - 错误：`user-login["用户登录"]` / `用户登录["用户登录"]` / `node.a["..."]`
   - 正确：`user_login["用户登录"]` / `node_a["..."]`
9. **标签内方括号必须转义**：节点显示文本若需出现 `[` 或 `]`，必须写成 HTML 实体 `&lbrack;` / `&rbrack;`，或替换为圆括号 `()`，防止破坏节点形状定义：
   - 错误：`A["Array[0] 值"]`
   - 正确：`A["Array(0) 值"]` 或 `A["Array&lbrack;0&rbrack; 值"]`
10. **标签内双引号**：节点文本若需包含双引号，统一替换为 `&quot;` 或单引号（`'...'`），不要在双引号包裹内直接写裸 `"`

## 图表质量与丰满度指引

1. **Anti-Triviality 原则**：当用户输入较为抽象或简短时（如"画一个微服务架构""画一个登录流程"），**不得生成少于 5 个节点的敷衍图表**。必须结合领域专业知识主动补充合理的子模块、边界条件、异常分支或上下游节点。一般目标节点数 5–15 个，具备实际参考价值
2. **布局走向自适应选择**：
   - 简单线性流程、节点少于 6 个、横向阅读更自然的场景 → 优先 `flowchart LR`（横向布局）
   - 节点较多、包含深层分支、子图（`subgraph`）、多角色或多层级时 → **必须使用纵向布局 `flowchart TB`**（避免页面横向溢出、提升可读性）
3. **跨图表通用**：当生成 ER 图时若用户描述简单，应主动扩展核心/外键/索引/必要关联表；类图应扩展关键属性、方法、继承关系；架构图应补充上下游/中间件/监控层

## 各图类型语法要点

### 基础流程图

**flowchart**：`flowchart <TD|TB|BT|LR|RL>`
- 节点形状：`id[text]` 矩形 / `id(text)` 圆角 / `id([text])` 体育场 / `id[[text]]` 子程序 / `id[(text)]` 圆柱 / `id((text))` 圆 / `id{text}` 菱形 / `id{{text}}` 六边形 / `id[/text/]` 平行四边形 / `id[/text\]` 梯形
- v11 形状语法：`A@{ shape: diamond, label: "Decision" }`（shape 名：rect/rounded/stadium/subproc/cyl/circle/diamond/hex/datastore/doc 等）
- 链接：`-->` 箭头 / `---` 无箭头 / `-.->` 虚线 / `==>` 粗线 / `~~~` 不可见 / `--o` 圆端 / `--x` 叉端 / `o--o` 双圆端 / `<-->` 双向 / `x--x` 双叉
- 带文本：`A-->|text|B`、`A-- text -->B`、`A-. text .-> B`、`A == text ==> B`
- 多目标：`A & B--> C & D`；链式：`A -- text --> B -- text2 --> C`
- 边属性：`A e1@--> B` 后接 `e1@{ animate: true }` 或 `e1@{ curve: linear }`
- 子图：`subgraph id [label]` ... `end`，子图内可 `direction TB`
- 样式：`classDef name fill:#f9f,stroke:#333;` / `class nodeId name;` / `A:::name --> B` / `linkStyle 0 stroke:#ff3;`（索引按边声明顺序 0 基）/ `style id fill:#f9f;`
- 注释：`%%` 到行尾
- Markdown 字符串（反引号）须配 frontmatter `config: htmlLabels: false`

**sequenceDiagram**：
- 参与者：`participant A as Alice` / `actor A`；类型 `participant A@{ "type": "database" } as DB`（type: boundary/control/entity/database/collections/queue）
- 箭头：`->` `-->` `->>` `-->>` `-x` `--x` `-)` `--)` `<<->>` `<<-->>`
- **激活符位置硬约束**：`+`/`-` 必须紧贴箭头尾部或头部（如 `A->>+B:`），严禁在激活符与冒号之间加空格（`A->>+B :` 会报错）。同样适用于反方向 `-->>-` / `-x+`
- 创建/销毁：`create participant B` / `destroy Carl`（销毁用 `-x`）
- 注释：`Note right of A: text` / `Note over A,B: text`
- 块：`loop`/`alt`+`else`/`opt`/`par`+`and`/`critical`+`option`/`break` ... `end`
- 背景高亮：`rect rgb(191,223,255)` ... `end`（可嵌套）
- 分组框：`box rgb(191,223,255) Label` ... `end`
- 自动编号：`autonumber`
- **纵深防重叠**：参与者超过 5 个时，建议在适当位置插入 `autonumber`（自动编号，避免歧义），并在交互密集区使用 `box ... end` 分组（按角色/子系统）
- 换行：`<br/>`

**stateDiagram-v2**：
- 状态：`s1` / `state "描述" as s2` / `s2 : 描述`
- 转换：`s1 --> s2` / `s1 --> s2: label`
- 开始/结束：`[*] --> s1` / `s1 --> [*]`
- 复合状态：`state First { ... }`（可嵌套）
- 选择/分叉/汇合：`state f <<choice>>` / `state f <<fork>>` / `state f <<join>>`
- 并发：复合状态内用 `--` 独占行分隔并发区域
- 注释：`note right of s1` ... `end note` / `note left of s2 : text`
- 方向：`direction LR`
- classDef 不能用于 `[*]` 或复合状态

**swimlane-beta**（v11.16.0+）：
- `swimlane-beta <direction>`，仅顶层 `subgraph` 渲染为泳道
- 节点/边语法同 flowchart
- 泳道标签含空格用 `subgraph id [label]`

### 结构关系图

**classDiagram**：
- 类：`class Name` / `class Name["标签"]` / `` class `Name with spaces` `` / 关系中隐式定义
- 成员：`Name : +Type attr` / `Name: +method() ReturnType`；块形式 `class Name { +String owner +deposit() bool }`
- 可见性：`+` public / `-` private / `#` protected / `~` package
- 泛型：`class Square~Shape~{ }`；字段/返回类型 `List~int~`；嵌套 `List~List~int~~`（需双 `~` 收尾）
- 关系（8 种）：`<|--` 继承 / `*--` 组合 / `o--` 聚合 / `<--` 关联 / `--` 实线链接 / `<..` 依赖 / `<|..` 实现 / `..` 虚线链接（箭头朝左/朝右两种等价写法）
- 基数：`Customer "1" --> "*" Ticket : label`
- 双向：`Animal <|--|> Zebra`
- Lollipop：`bar ()-- foo`
- 注解：`class Shape <<interface>>` 或块内首行 `<<interface>>` / `<<enumeration>>`
- 命名空间：`namespace Name { ... }`，可嵌套、可点号分层
- 方向：`direction RL`（不用 TD）

**erDiagram**：
- 关系：`A ||--o{ B : label`（基数左 `||`/`|o`/`}|`/`}o` + 线 `--`/`..` + 基数右 `||`/`o|`/`|{`/`o{`）
- 基数：`||` one / `|o` zero-one / `}|` one-many / `}o` zero-many
- 属性块：`ENTITY { type name type name PK type name PK, FK string? middleName string(99) field "comment" string[] parts }`
- 属性键：`PK`/`FK`/`UK`，组合 `PK, FK`；可空 `?`；长度 `string(99)`；数组 `string[]`
- 单词别名：`MANUFACTURER only one to zero or more CAR : makes`（`to`=实线，`optionally to`=虚线）
- 方向：`direction TB`/`direction LR`

**C4 图**（5 个关键字首行）：
- 元素函数（括号 + 逗号，alias 裸标识符，label 双引号）：`Person(alias, "label", "descr")` / `System` / `Container` / `Component` / `System_Ext` / `ContainerDb` / `Boundary` / `Deployment_Node`
- **参数顺序硬性绑定**（顺序错位会被解析器吞掉/渲染异常）：
  - `Person(alias, "label", "descr")` —— 3 个参数
  - `System(alias, "label", "descr")` —— 3 个参数
  - `Container(alias, "label", "technology", "descr")` —— **第 3 个参数必须是 technology**，若没有技术栈必须传空字符串 `""` 占位：`Container(db, "数据库", "", "存储数据")`，否则第 3 格的 descr 会被当成 technology 渲染
  - `Component(alias, "label", "technology", "descr")` —— 同上，technology 必传（第 3 位），无则 `""`
  - `ContainerDb` / `System_Ext` / `Deployment_Node` 各自签名见上规则一致
- 边界嵌套：`Enterprise_Boundary(b0, "Bank") { Person(customerA, "...") }`
- 关系：`Rel(from, to, "label", "techn")` / `BiRel` / `Rel_U`/`Rel_D`/`Rel_L`/`Rel_R`/`Rel_Back`
- 样式：`UpdateElementStyle(name, $bgColor="grey")` / `UpdateRelStyle(from, to, $textColor="blue", $offsetX="5")` / `UpdateLayoutConfig($c4ShapeInRow="3")`
- `title` 是图内指令（非 frontmatter）
- **不要输出** `AddElementTag`/`Legend`/`RoundedBoxShape()` 等未支持函数

**requirementDiagram**：
- 需求类型（6 种，均以 requirement 结尾）：`requirement`/`functionalRequirement`/`performanceRequirement`/`interfaceRequirement`/`physicalRequirement`/`designConstraint`
- 需求块：`requirement name { id: 1 text: ... risk: high verifymethod: test }`（risk: low/medium/high；verifymethod: test/inspection/analysis/demonstration）
- 元素块：`element name { type: simulation docRef: ... }`
- 关系（7 种）：`source - contains -> dest` / `<- copies -`（类型：contains/copies/derives/satisfies/verifies/refines/traces）
- 方向：`direction LR`

### 时间规划图

**gantt**：
- `gantt` + `title` + `dateFormat YYYY-MM-DD` + `section`
- 任务：`任务名 :状态, id, start, duration`（状态 active/done/crit/milestone/vert 必须在 metadata 最前）
- 依赖：`after a1`（多依赖空格分隔 `after b a`）；`until taskId`
- duration 单位（大小写敏感）：`ms s m h d w M y`（`M`=月，`m`=分）
- `excludes weekends`（不接受 `weekdays`，会被忽略）/ `excludes 2025-01-01` / `weekend friday` / `tickInterval 1week` / `todayMarker off`
- `axisFormat %Y-%m-%d`

**timeline**：
- `timeline` 或 `timeline TD`（方向同行）
- `title` + `section` + 事件行 `时间点 : 事件` / 多事件 `: 事件1 : 事件2` / 续行 `: 事件`

**kanban**：
- `kanban` + 列 `columnId[Column Title]`（或 `[Title]` 或纯文本）
- 任务（缩进在列下）：`taskId[Task Description]@{ assigned: 'knsv', ticket: MC-2037, priority: 'High' }`
- priority 仅 4 档：`'Very High'`/`'High'`/`'Low'`/`'Very Low'`（无 Medium）
- 缩进决定层级（任务必须比列缩进更多）

**journey**：
- `journey` + `title` + `section` + `任务名: 分数: 参与者1,参与者2`（两个冒号，分数 1-5）

**pie**：
- `pie` 或 `pie showData`（showData 是关键字，显示数值）+ `title`

### 数据决策图

**sankey**：
- `sankey` + CSV 数据行 `source,target,value`（**不写表头行**；value 是数字）
- 字段含逗号用双引号包裹：`"Heating and cooling, homes"`；字段内双引号成对转义 `""`
- frontmatter：`sankey: showValues: false` / `linkColor: source` / `nodeAlignment: left`

**xychart**（关键字全小写）：
- `xychart` 或 `xychart horizontal`
- `title "..."` / `x-axis [cat1, "cat2", cat3]` 或 `x-axis "title" 0 --> 100` / `y-axis "title" min --> max`（**y-axis 只能数值范围，不能分类**）/ `bar [...]` / `line [...]`
- 范围用 `-->`（两侧空格）；分类数组用 `[]`（含空格的类别各自加引号）
- 配置键是 `xyChart`（驼峰），非关键字

**quadrantChart**：
- `quadrantChart` + `title` + `x-axis Low --> High` + `y-axis Low --> High` + `quadrant-1`..`quadrant-4`（1=右上，2=左上，3=左下，4=右下，逆时针）
- 数据点：`Name: [x, y]`（**x、y 必须在 0..1 范围内，越界报词法错误**）
- 点样式：`Name: [0.3, 0.6] radius: 12, color: #ff3300` 或 `Name:::className: [0.3, 0.6]`

**radar-beta**：
- `radar-beta` + `axis a["Math"], b["Science"]`（多行 axis 累加）+ `curve alice{85, 90}`（**位置曲线值数必须等于轴数**）

**treemap-beta**：
- `treemap-beta` + 缩进层级（**层级完全由缩进表达**）
- section：`"Section Name"`；叶子：`"Leaf Name": value`（value 数字，>= 0）

### 架构集合因果图

**architecture-beta**：
- `architecture-beta` + `direction LR|TB`
- `group api(cloud)[API]` / `service db(database)[Database] in api` / `junction j1`
- 边（**端口方向两侧必填，绝不可省略**）：`db:L -- R:server` / `src:B --> T:db`；跨 group 带 `{group}` 限定
- **端口缺失必报错**：`server --> db`（未指定端口）会直接抛 parse error。必须写成 `server:R --> L:db` 或 `db:L -- R:server` 等显式端口形式。端口方向限 `T`/`B`/`L`/`R`
- `align row a b c` / `align column a b`
- 图标：内置（cloud/database/server）或 `logos:aws-lambda`

**block**：
- `block` + `columns 3` + 块 `id["label"]` / `id:W`（占 W 列）/ `space` / `space:N`

- 边：`A --> B` / `A -- "text" --> B` / `A - B`

**packet**：
- `packet` + 字段 `start-end: "Field name"` / `106: "Single bit"` / `+16: "Relative width"`

**venn-beta**：
- `venn-beta` + `set A` / `set B["Label"]` + `union A,B["Overlap"]`（**重叠用 union，不要用 intersection**）

**ishikawa-beta**：

- 第 1 行顶格=根问题；缩进 1=主类别；缩进 2=原因；缩进 3=子类别，其下再缩进=原因

**wardley-beta**：

**cynefin-beta**：

### 思维事件图

**mindmap**：
- `mindmap` + `root((中心))` + 缩进层级
- **唯一根节点约束**：全图必须且只能有一个 `root` 根节点。严禁在根级别出现多个并列顶层节点，否则解析为非法结构。子分支内同级节点无限制
- 节点形状：`id[text]` / `id(text)` / `id((text))` / `id))text((` / `id)text(` / `id{{text}}`
- 图标：`::icon(fa fa-book)`（双冒号）；类：`:::className`（三冒号）--二者下一行单独成行
- Markdown 字符串：`` id1["`**Root**`"] ``

**treeView-beta**：
- `treeView-beta` + 缩进式或 box-drawing 式（`├──` `└──` `│`），**两种不可混用**
- 标签含空格必须双引号；注解 `:::class` / `## desc` / `icon(name)`

**eventmodeling**：
- `eventmodeling` + `tf 01 ui CartUI` / `tf 02 cmd AddItem [[AddItem01]]` / `tf 03 evt ItemAdded`
- 实体类型：`ui`/`pcr`/`cmd`/`rmo`/`evt`（紧凑式）或 `timeframe`/`processor`/`command`/`readmodel`/`event`（宽松式，不可混用）

**gitGraph**：
- 头部用 **bare `gitGraph`**（不要方向后缀，默认 LR）

## 禁止写法清单（oracle 实测会语法报错，绝对不要输出）

1. **gitGraph 方向后缀**：`gitGraph LR` / `gitGraph TB` -> 用 bare `gitGraph`
2. **gitGraph SQUASH 等合并类型**：`merge x type: SQUASH`/`REBASE`/`FAST_FORWARD` -> type 仅 NORMAL/REVERSE/HIGHLIGHT
3. **gitGraph cherry-pick 后缀**：`commit id:"x" &feature/y` -> 用独立 `cherry-pick id:"..."` 关键字
4. **gitGraph cherry-pick merge commit 无 parent**：cherry-pick 一个 merge commit 时必须带 `parent:"父id"`，否则报错
5. **venn intersection/logics**：`intersection(A,B)` / `logics` -> 重叠用 `union A,B["label"]`
6. **xychart y 轴分类**：`y-axis [a, b, c]` -> y-axis 只能 `min --> max` 数值范围
7. **quadrantChart 坐标越界**：`Name: [9, 0]` / `[1.5, 0.3]` -> x、y 必须 0..1
8. **pie 负值**：`"A": -5` -> value 必须 >= 0
9. **bare 关键字用于强制 -beta 图**：`radar` / `wardley` / `architecture` / `venn` / `cynefin`（不带 -beta）-> 必须带 -beta
10. **C4 未支持函数**：`AddElementTag` / `Legend` / `RoundedBoxShape()` -> 不要输出
11. **requirement 自创类型**：`securityRequirement` 等 -> 仅 6 种文档化类型
12. **requirement 自创关系**：`depends` / `implements` -> 仅 7 种（contains/copies/derives/satisfies/verifies/refines/traces）
13. **classDiagram 方向 TD**：用 `direction TB`（classDiagram 不用 TD）
14. **sequenceDiagram 激活符与冒号之间加空格**：`A->>+B : msg` -> 必须 `A->>+B: msg`（激活符紧贴箭头，冒号紧贴消息）
15. **flowchart 直接链接到子图 ID**：`A --> subgraph_id`（部分渲染器不兼容）-> 必须链接到子图内部的具体节点，如 `A --> B_inside_subgraph`
16. **stateDiagram-v2 Note 多行/单行混用**：单行 Note 必须 `note left of S1 : 文本`；多行 Note 必须 `note left of S1\n多行内容\nend note` 闭合。两种格式严禁混用同一 Note 块

## 不推荐写法（能解析但应避免）

- **gitGraph `commit "字符串"` / `commit msg:"x"`**：未文档化 shorthand，用 `commit id:"..."` / `tag:"..."` 更规范
- **cynefin `look: handDrawn`**：cynefin 不支持 handdrawn 渲染（不会报语法错，但渲染异常）
- **sankey CSV 表头行**：`source,target,value` 会被当成数据行，省略它
- **radar 位置曲线值数 ≠ 轴数**：语法不报错但渲染错乱，值数必须等于轴数
- **gantt `excludes weekdays`**：被忽略（不排除任何日期），用 `excludes weekends`

## Frontmatter（可选，全图通用）

11.16.1 内置 processFrontmatter，所有图表支持开头 frontmatter（YAML）。非必须，简单图省略。仅当需要配置渲染参数时使用：

```
---
title: <图表标题>
config:
  <图类型键>:
    <参数>: <值>
  themeVariables:
    <变量>: <值>
---
<图表关键字>
<图表体>
```

frontmatter 必须在代码最开头，首行 `---` + YAML + 闭合 `---`。常用：sankey `showValues: false`、pie `donutHole`/`legendPosition`、gitGraph `showBranches`、xyChart `showDataLabel`、quadrantChart `chartWidth`、radar/treemap 配置。

## 补充安全与质量约束（绝对执行）

以下为对前述规则的强约束与精炼总结，每次输出都必须无条件遵守。重复内容已与上文对齐，作为兜底提示。

### 1. 节点 ID 与文本安全硬性规则
- **ID 命名限制**：所有节点/组件 ID 必须仅由字母、数字、下划线组成（`[a-zA-Z0-9_]`），绝对禁止使用中文、空格、横线（`-`）作为 ID（例如：用 `node_a` 而非 `node-a` 或 `节点A`）
- **特殊字符转义**：节点显示文本中若包含方括号 `[]`，必须写成 `&lbrack;` 和 `&rbrack;`，或替换为圆括号 `()`，防止破坏节点形状定义
- **换行符**：节点内换行统一使用 `<br/>`，严禁在字符串中直接敲回车或 `\n`（即便 flowchart 显式开启 Markdown 字符串模式）

### 2. 特定图表严格参数签名
- **C4 参数对齐**（顺序错位直接渲染异常）：
  - `Person(id, "Label", "Description")`
  - `System(id, "Label", "Description")`
  - `Container(id, "Label", "Technology", "Description")` —— **第 3 个参数必须是 Technology**，无技术栈时传 `""`
  - `Component(id, "Label", "Technology", "Description")` —— **同上**
- **Architecture-beta 端口绑定**：连接必须显式指定端口方向（`T`/`B`/`L`/`R`），例如：`server:R -- L:db`，禁止省略端口方向
- **Mindmap 唯一根节点**：全图必须且只能有一个 `root` 根节点

### 3. 图表质量与专业度增强
- **内容丰满度**：面对模糊或简短的用户输入，必须结合专业知识扩展内容，生成包含 5–15 个节点、具备实际参考价值的完整图表，严禁生成 2–3 个节点的敷衍图表
- **自适应布局**：简单线性流程、节点少于 6 个时使用 `LR` 方向；复杂分支、包含子图或节点超过 6 个时，必须使用 `TB` 方向
